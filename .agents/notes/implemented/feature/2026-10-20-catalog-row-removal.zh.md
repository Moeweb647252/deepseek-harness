# Agent Note: 会话页头的目录行移除

Status: implemented

[English](2026-10-20-catalog-row-removal.md) | 中文

## 问题

会话页头的目录会列出某个 Session 的每个直接子级，并持续到该日志结束。委派过许多一次性任务的父会话会把这些任务一直留在计数、切换器与工作区谱系中，却没有办法停止显示其中一项。目录是 parent 自有的持久状态，由 `list_agents`、浏览器投影与工作区树读取，因此仅在 Client 隐藏某一行会与发现结果不一致、在重新加载后消失，并让计数继续报告树中已不再显示的子级。改为删除子 Session 则会破坏用户仍可能需要阅读的记录。

## 决策

移除是退役一个目录身份，而不是删除任何东西。浏览器以 `{ parentSessionId, childSessionId }` 调用 `ctx.remote.subagents.retire`；Host 解析该 parent 的在线 Agent，通过 `retireCatalogChild()` 追加版本 3 的 `subagent/catalog` 退役记录，并返回 `{ retired: true }`。[父目录说明](../architecture/2026-09-01-parent-owned-subagent-catalog.zh.md)负责折叠与投影，[退役格式记录](../../../../docs/persistence-changes/2026-10-19-subagent-catalog-retirement.zh.md)负责版本 3 载荷；本次变更只为该目录自有操作增加一个浏览器入口。

记录只点名一个身份，且移除只改变 parent 的目录列表。子级的运行、Session 日志与 Session 记录不受影响且保持可读，投影把该身份从计数、切换器与谱系中移除，而同一身份之后的新建立记录会再次列出它。退役一个目录中未列出的身份不会改变任何视图，并且会被接受，因此重复与并发的调用会收敛而不是失败，对已移除的行再次移除也不算错误。该操作是同步的，因为它只向一个 parent Session 追加一条记录。

`external` 行没有可退役的本地 Session，因此不显示该按钮；切换器当前显示的那一行也不显示，因为移除它会让一个导航控件以消失作答。该行子级正在运行时按钮保持可见但被禁用：退役记录是持久的，移除运行中的子级会让在线工作从计数、切换器与工作区树中消失，而它仍在运行并继续消耗。因此由 Client 拒绝提供该移除，并由被禁用的控件说明原因；Host 仍然接受来自任何其他调用方的此类调用，因为追加一条持久记录并不是它可以针对展示选择强制的不变式。调用失败会在菜单主体中、目录树上方渲染本地化的 `role="alert"` 提示，并保持菜单打开且该行及其控件仍在原处，目录因此不会声称一次并未发生的移除；调用成功不需要客户端改动，因为实时 projection 帧会移除该行。

## 已考虑的替代方案

**把被移除的 id 保存在 Client 本地的隐藏集合中。** 它不需要 Host 改动，但隐藏效果会在重新加载和另一个浏览器中消失，与 `list_agents` 不一致，并让页头计数继续报告切换器已不再提供的子级。

**删除子 Session。** 移除之所以存在，是因为列表过长，而不是因为记录不再需要；删除 Session 是另一项破坏性操作，有自己的确认流程，而子 Session 正是谱系可读性的来源。

**通过删除建立事件来重写目录。** Session 日志是仅追加的，投影状态由它们派生，因此重写历史会改变每个更早读取者的答案，并与[已发布格式迁移规则](../architecture/2026-08-31-released-session-format-migrations.zh.md)冲突。

**新增专门的移除事件类型。** 版本 3 退役记录已经点名一个身份，第二套移除词汇会把退役语义拆到两个折叠中。

**在 Host 中拒绝运行中的子级。** 服务的职责是追加一条持久记录，而运行无论如何都会继续；拒绝会让某个客户端的展示决定变成服务的不变式，也会拒绝一个已明确决定该在线行不再需要的调用方。

## 后果

被退役的子级从 `list_agents`、页头计数、切换器与工作区树中消失，而按 Session id 直接寻址的操作仍然可用：`send_message`、`interrupt_agent` 与任务归属都不查询目录，因此只要调用方仍知道该子级身份，就仍能寻址它。子级的运行、Session 日志与 Session 记录不受影响，因此移除只是展示层行为，绝不能替代停止或删除成员。

退役在存储上并非免费：记录保留在 parent 日志中，移除 N 个子级会追加 N 条记录。它也不是永久排除，因为只要后续的建立记录再次点名该身份，折叠就会重新列出它。向已退役子级发送提示词不受影响：继续执行通过子级自己的 header 谱系寻址，绝不重新读取 parent 目录，因此调用方只要仍知道该身份，该子级就仍可继续。

目录同样拥有行的标题，而不只是成员关系，因此[重新标注记录](../../../../docs/persistence-changes/2026-10-21-subagent-catalog-relabel.zh.md)正是该决策为其留出空间的同类记录：它就地替换某个已列出行的标签而不触碰成员关系，Sidebar 聊天页签也从同一目录标签取标题。标签属于展示层，因此移除与重新标注都不会改变子级是什么，也不改变它能否被继续执行。
